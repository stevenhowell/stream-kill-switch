# Research behind the switch

Found by web search on 2026-10-21; abstracts read, full texts not. Use each for what it contributes, not as a blanket citation.

| Paper | What it shows | What it gives the switch |
|---|---|---|
| Sun et al., "Fast Best-of-N Decoding via Speculative Rejection", NeurIPS 2024, arXiv 2410.20290 | Score partial generations with a reward model and drop the weak ones early; 16–32x less compute for the same reward as Best-of-N | The precedent. Best-of-N with early kill is the stretch goal: start four streams, judge at token 50, keep the best |
| Manvi, Singh, Ermon, "Adaptive Inference-Time Compute: LLMs Can Predict if They Can Do Better, Even Mid-Generation", arXiv 2410.02725 | The generator predicts mid-generation whether restarting would do better; 50–75% of samples pruned early with little loss | Same idea with the model judging itself. The switch uses an outside judge, so it works on any model and needs no training |
| Manvi et al., "Zero-Overhead Introspection for Adaptive Test-Time Compute", arXiv 2512.01457 | Predicts reward and remaining length at every token | Where this goes next: a judge that also predicts how long the tail is |
| Dou et al., "What's Wrong with Your Code Generated by Large Language Models?", arXiv 2407.06153 | 5,072 bugs from seven models in three primary types (syntax, runtime, functional) and twelve secondary | Which faults are visible early (syntax precursors, contract faults) and which are not (functional). The switch and the tests split the work |
| Spracklen et al., "We Have a Package for You!", USENIX Security 2025, arXiv 2406.10279 | 576,000 samples, 16 models: at least 5.2% of commercial-model and 21.7% of open-source samples import a package that does not exist; 43% of those names repeat on rerun | The `bad_import` rule, with the allowed list passed as data |
| Dai et al., "Process Supervision-Guided Policy Optimization for Code Generation", arXiv 2410.17621 | Line-level process rewards during generation | A trained judge of partial programs. The switch is the untrained, inference-time version with the rules written down |
| DreamPRM-Code, arXiv 2512.15000 | Function-as-step process reward model with unit tests as the clean final label | Same, and the reason the demo uses tests as the referee |
| Ridnik, Kredo, Friedman, "Code Generation with AlphaCodium", arXiv 2401.08500 | Tests first, then generate and fix against them; GPT-4 pass@5 on CodeContests 19% → 44% | The flow the switch sits inside: it guards the generate step |

Jev is not trained on any of this. It reads `state` and answers typed questions. The papers tell you which questions to ask.
